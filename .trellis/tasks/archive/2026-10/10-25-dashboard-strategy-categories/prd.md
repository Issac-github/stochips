# 策略概念分类与人工模式标记

## Goal
把现有页面扩展为按策略概念查阅的数据工作台，重点区分各类平台突破，并让观察池可保存人工模式分类。

## Requirements
- 新增“策略分类”页，涵盖情绪与空间、主线与梯队、龙头与助攻、量能与弱转强、平台与反包、竞价与分时、风控与跟踪。
- 每类集中展示概念核对卡、关联收盘事实和对应的已保存复盘；字段计数仅表示来源记录，不是匹配股票或信号数。
- 小平台、大龙头天量平台、小龙头天量平台、趋势龙头平台四类独立展示，说明缺少连续日线/历史成交量/整理结构验证，不把前高记录直接认定为平台。
- 观察池新增可多选的人工模式标记，支持未分类/按模式筛选、列表展示、备注、持久化和导出。分类是人工观察标签，不表示已验证。
- 静态概念目录一份JSON供Python与React使用；不复制私有方法原文、固定交易阈值或概率。
- 独立SQLite增量增加模式标记表，保留既有数据与revision锁；旧客户端省略concepts时保留原标记。新接口默认空数组，未知/重复/过多/类型错误标记拒绝。
- 复用Details并限制每类可见数据集，保留所有字段。切换分类/日期重置搜索与弹窗，不改市场数据计算。
- 仅本地实现、验证、一个提交；不推送或生产部署。

## Acceptance Criteria
- [x] 七类入口、平台四类及证据边界清晰，空数据/非标准复盘完整回退。
- [x] 观察池人工标记可保存、刷新保留、过滤与导出；与原始角色及验证结果分开展示。
- [x] 既有SQLite升级不丢记录；旧请求保留分类；严格校验、用户隔离和冲突保持。
- [x] lint/build、前后端测试和桌面/手机布局检查通过。

## Decisions
- 采用单一静态目录 + 来源数据关联 + 人工分类，复用现有认证和观察池存储。
- 不以Markdown关键词、连板高度、换手率、前高记录自动推断策略模式；不新增行情采集或交易信号。
