# 按日期保存的次日观察池

## Goal
把现有复盘候选集中为可保存、可跟踪的个人观察清单，串联事实依据、反证、待验证条件与人工复核结果。

## Requirements
- 新增次日观察池标签，按报告日期合并核心连板、助攻候选、前高突破，同代码合并角色和来源，不新增评分或买卖信号。
- 每项显示原始事实依据、来源、风险、竞价/盘中待验证条件；完整复盘仍是情绪/主线判断来源。
- 支持待观察、关注、剔除，可恢复；记录待验证/条件满足/未满足/继续观察及备注。记录标明人工复核，不由涨停与否自动判定。
- 服务端按飞书 tenant/open_id + 日期 + 股票保存独立 SQLite 记录与来源快照；跨浏览器与重启保留。行情 MySQL 维持只读。
- 后续首个可用行情日反馈按数据库实际记录展示，缺失抓取不能视为未涨停/跌停，不假装已覆盖紧邻下一交易日。
- 保存须认证、Origin+CSRF 校验、有限 JSON 请求、严格字段校验及 revision 乐观锁；不同用户隔离。失败保留编辑内容并可重试。
- 搜索、状态/角色过滤、观察池 JSON 导出；空池、读取失败、日期切换明确处理。
- Docker 持久卷保存观察记录；运行时数据忽略 Git/同步镜像，更新文档和接口规范。

## Decisions
- 用户已接受上轮提出的观察池第一版并要求执行，按现有登录身份持久化而非浏览器本地存储。
- 仅结构化汇总已有报告来源；不从自由 Markdown 猜测个股推荐/情绪。保存后的来源消失时保留快照并显式标记。
- 后续竞价/分时接入、自动规则回测、任意加股及服务器部署不在本轮。

## Acceptance Criteria
- [x] 同股多来源去重且所有依据可追溯；零与空值不混淆。
- [x] 关注/剔除/恢复、人工结果和备注按用户日期保存，重启后可读；并发冲突409不覆盖。
- [x] 来源消失仍保留已保存记录；后续缺失数据不生成负反馈结论。
- [x] 未授权、CSRF、非法/过大请求被拒绝，无行情写入。
- [x] lint/build、观察池逻辑与HTTP测试、桌面/手机交互检查通过。
