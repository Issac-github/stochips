# 按策略阅读顺序突出看板重点

## Goal
将 dashboard 从行情汇总首页调整为收盘策略复盘首页，让用户先读已有研判，再核对高标与助攻证据，最后查看完整市场数据。

## Requirements
- 默认进入“策略复盘”，按已有 Agent 五节输出展示情绪定位、主线与梯队、龙头与助攻、风险与反证、次日验证清单。
- 风险与次日验证在桌面端放在研判旁，移动端依次阅读；内容使用已保存复盘，不重新生成、不截取结论或新增打分。
- 五节格式完整才能分卡；未知格式、重复或缺失标题时完整显示原文，避免遗漏反证。
- 突出核心连板、昨日高标反馈和助攻候选，可跳转对应全部明细。
- 明确天量、竞价、分时等当前不可验证条件；换手不能等同历史天量，收盘候选不证明有效一字助攻或因果。
- 原有图表归入“市场数据”；全部明细、完整复盘、原文和导出保留。
- 仅做显示层重组；无新行情获取、交易建议、仓位、后台写入或生产部署。
- 内部方法论文档保持私有，不在页面或提交中复制原文。

## Acceptance Criteria
- [x] 默认策略页展示已保存五节复盘和事实观察表，缺失复盘有明确空态。
- [x] 历史非标准 Markdown 和代码块不被错误拆分或静默丢弃。
- [x] 空值、零换手、无助攻、缺少昨日高标记录均保留正确语义。
- [x] 证据链接打开对应明细；日期切换、刷新、导出和登录行为保持。
- [x] 通过 lint、typecheck/build、Markdown 拆分回归测试、桌面/移动端浏览器检查。

## Verification
- Node 22: ESLint、TypeScript/Vite build、5 项 Markdown 解析测试。
- 本机隔离 HTTP fixture：完整五节、缺失分析/空表、历史格式原文保留、503 清除旧数据；证据跳转核心明细，0 与 null 区别展示，市场图表按需加载。
- Chrome 桌面及 iPhone SE 375px：卡片布局、风险提前、文本及表格响应式检查。fixture 在仓库外，不修改生产认证。
- 图表拆包后首屏 JS 从约 1994KB 降至 1447KB（gzip 634KB → 452KB）。无服务器部署。

## Technical Approach
- 复用 `daily_review.content` 的五节输出合约，不改变 HTTP/数据库。
- 提取共用 Markdown、市场图表和独立策略页面组件；新增纯展示用途的保守标题分节函数。
- 复用 `top_stocks`、`previous_high_feedback`、`leader_assists` 的原始后端顺序与字段。
- 数据集选择由 App 控制，支持策略页面跳转。
