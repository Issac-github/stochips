# 近三个月涨停数据与连板龙头交易体系复核

## Goal

读取服务器 192.0.2.10 的 Docker 数据库和用户指定的交易体系文档，用近三个月实际记录评估策略规则、数据可靠性和可验证边界。

## Requirements

- 时间窗口：2026-07-02 至 2026-10-02，明确数据库实际覆盖区间及交易日缺口。
- 盘点所有业务表，定位涨停、炸板、连板、板块、行情及已有 AI 复盘的关系。
- 以服务器 services/agent/chain/wiki/raw/001-连板龙头交易体系.md 为方法论来源。
- 逐条映射可量化规则；分析晋级、断板、重启、市场环境及可获得的后续表现。
- 区分描述统计、代理指标与可执行收益回测，列明数据缺失、交易可达性、时点及幸存者偏差。
- 不修改数据库、不触发交易、不变更生产服务。
- 输出中文分析与可复查统计证据；不保存认证信息。

## Acceptance Criteria

- [x] 表结构、数据覆盖、缺失及重复检查完成。
- [x] 策略文档规则与可用字段形成映射。
- [x] 核心统计独立交叉核对，保留样本量、时间和口径。
- [x] 结论说明策略问题、证据强弱及后续验证优先级。

## Results

见 `research/audit-report.md`、`research/statistics.json`、`research/sql-verification.json`。共盘点 12 张表，主要行情 63 个交易日；全窗口主板高标 268 个观察，可比窗口 255 个观察。只读 SQL 与本地统计一致。没有应用、数据库结构或生产服务变更，项目构建与前端检查不适用。

## Technical Approach

复用已授权 SSH 会话，读取 Docker 运行状态；通过现有应用数据库配置建立只读会话，不输出凭据。仅对研究所需字段进行聚合或导出，不改应用代码。

## Scope Decisions

- 用户已明确授权服务器检查和三个月分析，直接进行研究。
- 拓展考虑：今后可重复审计、不同市场状态对照、完整行情与实际成交约束；本次仅实施已有数据支持的分析。
- 无需用户确认的技术选择：以实际交易日序列而非日历天计算相邻日。

## Out of Scope

自动交易、策略参数生产变更、数据库修复、Clash 修复、无完整价格与成交假设的收益承诺。
