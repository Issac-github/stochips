# 基于已有数据迭代验证连板续板候选策略

## Goal

按用户要求反复测试已有服务器市场快照，形成一份独立的新策略文档，提高可解释的次日续板命中率，并披露候选覆盖、失败样本、时间验证和不可交易边界。

## Requirements

- 原策略文件不修改，生产环境不改动，禁止任何 Git 提交及会自动提交的归档/日志操作。
- 复用 2026-07-02—10-02 请求窗口内取回的数据；可比研究区间从 07-10 起，09-30 仅作为前日结果标签。
- 命中定义为 T 日收盘筛选后 T+1 再次进入涨停池；这不是盈利率，也不是成交概率。
- 用 T 日及以前字段构造规则，保持结果标签独立，禁止未来数据参与筛选。
- 区分一字高命中观察池与非一字观察池，不把一字的不可成交优势当交易收益。
- 分轮做基线、单因素、简短组合、时间验证、敏感性检查，报告全部搜索规模和淘汰理由。
- 7 月用于发现，8 月用于筛选，9 月用于冻结后的时间验证；明确 9 月汇总数据在之前审计中已看过，并非真正盲测。
- 不凭一个小样本最高值推荐规则；报告日期数、股票数、命中分子分母、跌停率、区间和失败案例。
- 新文档置于 docs/strategy/，附可复现脚本和结果路径；不替换 AI 当前读取的策略。

## Acceptance Criteria

- [x] 快照与标签一致性、时间边界、重复键检查通过。
- [x] 完成基线及多轮规则比较，保存结果与规则冻结记录。
- [x] 时间验证及参数敏感性明确，区分发现结果和验证结果。
- [x] 新策略写明可直接执行的筛选条件、观察流程、停止条件与未验证事项。
- [x] 原策略哈希不变，Git HEAD 不变且没有新提交。

## Results

新文档：`docs/strategy/2026-10-02-连板续板观察策略-v0.1.md`。预设 85 个规则，完成跨月边界修正、9 月时间验证、12 个敏感性诊断与周重采样。非一字主规则为 2—10 板、最终封板 <=10:00、开板 <=1、换手 <=20%；9 月全池 23/64，每日一只 9/20。改善尚不确定。一字换手 <=5% 未改善时间验证，淘汰该附加规则。原策略不动；用户禁止提交，因此不执行会自动提交的归档或日志命令。

## Decisions

用户明确授权基于现有数据研究并创建新策略文档。无需补采或服务器访问；不将本次优化解释为对原完整交易体系的证伪。交易成本、实际收益和竞价入场验证因数据不足不在本次计算范围。
